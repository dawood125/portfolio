## 1. Which tools (2025-2026) produce the best talking/presenting-person video from a single photo or short recording? Quality, lip-sync, voice cloning, length, pricing, Pakistan availability, commercial use

### Takeaway
There are two families: (1) general video models with native audio (Google Veo 3.1 in Flow; Kling; Runway) that generate a short cinematic 8-second shot including a synthetic voice, and (2) audio-driven "talking photo/avatar" tools (HeyGen Avatar IV, Hedra Character-3, Kling AI Avatar 2.0, Higgsfield Speak) that lip-sync a single image to a script or to YOUR OWN uploaded audio and can run for minutes. For Dawood, Google AI Pro (billed in PKR, ~Rs 5,600/mo) is the most accessible Veo route from Pakistan; Sora 2 is no longer an option (shut down in 2026); USD/Stripe-billed tools (HeyGen, Hedra, Kling, Runway) may need a card enabled for international recurring payments.

## 2. Step-by-step workflow for the viral "talking video portfolio" (photo -> stylized/full-body image -> animated clip -> background removal -> loop)

### Takeaway
The working pipeline is: (1) generate a consistent full-body still from the headshot with an identity-locking image model (Nano Banana Pro / Gemini 3 Pro Image, GPT-image, Flux); (2) animate it in Veo 3.1 (Frames/Ingredients to Video) with a short spoken line, or lip-sync it to his own audio with an avatar tool; (3) either generate on a plain background that matches the site colour (no alpha needed) or run AI background removal to ProRes 4444 / WebM-alpha; (4) trim to a seamless loop and encode for web. Unscreen-style one-click removers have consolidated; several newer tools export true alpha.

### Cited Findings
- Nano Banana Pro face consistency: use ~6 high-quality references ≥1024x1024 (front and three-quarter, even lighting); model supports up to 14 references but fidelity is best with ≤6; put the identity instruction first, then wardrobe, lighting, camera; use explicit lock language (eyes, nose, jawline, skin texture); iterate and diagnose drift by feature — [LaoZhang face-consistency guide](https://blog.laozhang.ai/en/posts/nano-banana-pro-face-consistency-guide); [Ilisai headshot prompts, Jul 2026](https://www.ilisai.com/en/blog/nano-banana-pro-headshot-portrait-prompts).
- No tested source template exists for headshot -> full-body; sources show the model doing full-body wide shots of characters when explicitly prompted — [LaoZhang](https://blog.laozhang.ai/en/posts/nano-banana-pro-face-consistency-guide).
- Veo character workflow: create the character as an image/"ingredient", keep it as reference, use up to three ingredients per prompt; frame with camera language ("wide shot", "close-up", "tracking shot") — [Google blog Flow tips](https://blog.google/innovation-and-ai/products/flow-video-tips/); [Veo3AI Ingredients guide](https://www.veo3ai.io/blog/veo-3-1-ingredients-to-video-guide-2026).
- Frames-to-Video (first + last frame) and Extend are available in Flow with audio — [Google blog Veo 3.1 updates](https://blog.google/innovation-and-ai/products/veo-updates-flow/). One guide suggests saving the last frame of a clip and starting the next generation from it for higher fidelity continuity — [Toolfolio](https://toolfolio.com/articles/make-videos-longer-than-eight-seconds-in-veo).
- Higgsfield's Veo prompt advice: put the exact spoken line in the prompt; use 16:9 for web/desktop; example phrasing "medium-wide framing … slow push-in; room ambiance" — [Higgsfield x Google](https://higgsfield.ai/blog/Higgsfield-Google-Bring-Your-Character-to-Life).
- Background removal with true alpha (vendor claims): Fliki — 3 min/month free with ProRes 4444 and WebM alpha export — [Fliki](https://fliki.ai/features/video-background-remover); VideoBGRemover — WebM (VP9) or MOV (ProRes 4444) with alpha — [VideoBGRemover](https://videobgremover.com/transparent-video/mov-prores); ExportAlpha — WebM alpha up to 60 s, ProRes 4444 up to 8 s per clip — [ExportAlpha](https://exportalpha.com/); LocalBG — offline/local processing, ProRes 4444 alpha on Pro tier — [LocalBG](https://localbg.app/).
- Runway's remover historically exported a green-screen MP4 or mask rather than a true alpha file, and free exports were capped at 720p (2024 guide) — [Gadgets To Use](https://gadgetstouse.com/blog/2024/12/31/remove-any-video-background-using-runway-ml/).
- Standard H.264 MP4 has no alpha channel; ProRes 4444 or VP9-alpha WebM are the compositing formats — [VideoBGRemover](https://videobgremover.com/transparent-video/mov-prores).
- Jake Archibald's recommendation: "Where possible, build animations with web technologies instead of video"; if video, use stacked alpha (AV1 + HEVC fallback) — [Jake Archibald](https://jakearchibald.com/2024/video-with-transparency/).

### Inferences
- Recommended concrete pipeline for Dawood (synthesis):
  1. Prep references: the 2048px headshot plus 3-5 extra phone photos (three-quarter angles, a full-length mirror/standing photo so the model knows his real build/height proportions). Body proportions are the main drift risk when inventing a full body from a chest-up headshot.
  2. Full-body still (Nano Banana Pro in Gemini app/Flow, which he'd already have with AI Pro). Example prompt: "Keep the exact face, skin tone, hair, beard and age of the man in the reference images. Full-body shot, head to shoes, standing relaxed facing camera with a slight three-quarter turn, navy blazer over black crew-neck shirt, charcoal trousers, black leather shoes. Plain seamless warm-cream studio backdrop (#F2EDE4), soft key light from front-left, subtle floor shadow, 50mm lens at chest height, photorealistic, 16:9 with subject centred and generous headroom. Do not alter facial features or body proportions." Generate 10-20 variants, pick the one he'd be comfortable meeting a client as.
  3. Animate in Flow (Veo 3.1 Fast for drafts, Quality for final). Example prompt: "[Frames to Video, start frame = still] The man smiles, makes a small open-palm welcoming gesture with his right hand and says in a warm, confident Pakistani-English accent: \"Hi, I'm Dawood — I build fast, beautiful web apps.\" Static locked-off camera, plain cream backdrop unchanged, no camera movement, natural blinking, ends in the same neutral pose as the first frame." Using the same image as start and end frame makes a seamless loop easier.
  4. For a 30-60 s spoken intro, record his own voice (phone + lav mic) and drive the still with Hedra Character-3 / HeyGen Avatar IV / Kling Avatar 2.0 instead of Veo dialogue.
  5. Background: simplest "transparent" look is to generate on a solid colour identical to the page background (cream or near-black) and set the page background to the exact sampled hex — no alpha encoding needed, works on every browser, smallest files. Only use alpha (ProRes 4444 -> WebM VP9 alpha + HEVC alpha, or stacked-alpha AV1/HEVC) if the character must float over moving/gradient content.
  6. Loop: cut on a neutral pose; crossfade 6-10 frames if needed; deliver silent muted loop for autoplay plus a separate click-to-play version with audio + captions.
- B&W desk variant prompt (synthesis): "Medium shot, man from reference seated at a wooden desk with an open laptop, looking into camera and speaking, practical desk-lamp key light from the left, deep shadows, black-and-white film look, shallow depth of field, static camera." Grading to B&W also hides small AI skin/texture artefacts.
- Stage-spotlight variant: generate (or shoot) full-body on pure black with a hard top-down spotlight; black backgrounds merge seamlessly into a dark-themed site without alpha.

## 3. How to embed the hero video performantly (transparent video, poster/LCP, autoplay rules, sound-on with captions, file sizes, lazy loading, mobile fallbacks, Next.js, hosting)

### Takeaway
Use a muted, playsInline, looping `<video>` with a sized poster (reserve the box to avoid CLS), keep the hero loop to roughly 0.5-3 MB, provide a separate click-to-play-with-sound version with a WebVTT `<track>`, and only use alpha if needed — preferably Jake Archibald's stacked-alpha approach (AV1 + HEVC, ~460 kB-1.1 MB) over native VP9-alpha/HEVC-alpha (1.1 MB / 3.4 MB). For a portfolio's traffic, self-hosting on Vercel (static/Blob, CDN included) is enough; Mux's free tier or Bunny Stream suit longer sound-on videos.

### Cited Findings
- Autoplay requires `muted`; `playsInline` is often required for autoplay on iOS Safari; Next.js docs: when using autoPlay "also include the muted attribute… and the playsInline attribute" — [Next.js Videos guide (v16.4, updated 2026-08-31)](https://nextjs.org/docs/app/guides/videos); compatibility table showing unmuted autoplay blocked on Chrome/Safari/iOS — [ImageKit autoplay in Next.js](https://imagekit.io/blog/nextjs-video-autoplay/).
- Next.js best practices: set width/height or CSS aspect-ratio so the box is reserved (avoids CLS); use `poster` especially with `preload="none"`; include fallback content; add captions via `<track>`; use native controls for keyboard/screen-reader accessibility; Vercel Blob for hosting (CDN handled automatically); third-party options listed: next-video (Vercel Blob/S3/Backblaze/Mux), Cloudinary `<CldVideoPlayer>` with adaptive bitrate, Mux, ImageKit `<IKVideo>` — [Next.js Videos guide](https://nextjs.org/docs/app/guides/videos).
- LCP: `<video>` elements are LCP candidates; their time is the earlier of the poster image loading or the first frame being presented; good LCP ≤ 2.5 s, poor > 4.0 s — [web.dev LCP](https://web.dev/articles/lcp).
- Size to display: serving video at displayed size is the single biggest optimisation (example: 4K source resized to 1280px went 63.76 MB -> 3.2 MB); strip the audio track from decorative loops (saves 10-30%) — [ImageKit Next.js video optimisation](https://imagekit.io/blog/nextjs-video-optimization/).
- Transparent video (Jake Archibald, 2024):
  - Stacked alpha: double-height video, colour on top, alpha as luma on bottom, recombined by a WebGL shader; alpha adds only ~8 kB; npm package `stacked-alpha-video` (a `<stacked-alpha-video>` web component wrapping a native `<video autoplay crossorigin muted playsinline loop>` with AV1 then HEVC sources); native controls not supported.
  - Sizes for the same clip: animated AVIF 504 kB; native VP9 alpha 1.1 MB; native HEVC alpha 3.4 MB; stacked AV1 460 kB; stacked HEVC 1.14 MB.
  - Encoding: stacked AV1 = libaom-av1 two-pass, -crf 45, -cpu-used 3, yuv420p, -an, +faststart; stacked HEVC = libx265 -preset veryslow -crf 30 -tag:v hvc1; native VP9 alpha = libvpx-vp9 -crf 45 -b:v 0 -pix_fmt yuva420p; native HEVC alpha practical only on macOS (Apple Compressor ~£50 beats ffmpeg hevc_videotoolbox by ~2x size); use 10-bit if gradients band.
  - Safari supports VP9 but not VP9 with alpha, so HEVC must be listed first; animated AVIF is not recommended (perf/Safari bugs); at time of writing Chrome Android rendered alpha incorrectly (fix in Canary) — [Jake Archibald, Video with alpha transparency on the web](https://jakearchibald.com/2024/video-with-transparency/).
- Browsers that play WebM/HEVC without understanding alpha show the video over a black background — [CSS-Tricks](https://css-tricks.com/?p=328311). The VP9/HEVC split is a licensing/standards split; Safari has supported VP9 since Safari 15 but not with transparency — [Rotato guide](https://rotato.app/read/transparent-videos-for-the-web).
- A September 2026 post reports FFmpeg can silently drop the alpha layer when converting Apple HEVC-with-alpha files (single report) — [hontran.dev](https://www.hontran.dev/blog/transparent-video-web-hevc-alpha-ffmpeg).
- Hosting: Mux free tier ≈ 100,000 delivery minutes/month, no card required (per one source); Bunny Stream bills by GB (storage from ~$0.01/GB/mo, delivery from ~$0.005/GB, free encoding) and is where indie devs often land after Mux; sources disagree ~9x on Mux per-minute delivery cost; no current Cloudinary video price found — [DevToolPicks](https://devtoolpicks.com/blog/best-mux-alternatives-indie-hackers-2026); [APICostCalc](https://apicostcalc.com/mux-vs-cloudflare-stream-vs-bunny-stream-cost-calculator.html); [PkgPulse](https://www.pkgpulse.com/guides/mux-vs-cloudflare-stream-vs-bunny-stream-video-cdn-2026).

### Inferences
- Recommended hero markup pattern (synthesis): `<video autoplay muted loop playsinline preload="metadata" poster="/hero-poster.avif" width=… height=… aria-hidden="true">` with sources AV1 MP4 (`codecs=av01…`) -> HEVC/H.264 MP4 fallback (or stacked-alpha component if alpha needed). Separate visible "Play intro with sound" button that opens a dialog/inline player with `controls`, the audio version, and `<track kind="captions" src="intro.en.vtt">`.
- File-size targets (inference from cited numbers): hero loop 6-10 s, 720-1080p wide (or ~720-900px wide for a standing figure), ≤1.5 MB AV1 / ≤2.5 MB H.264 desktop; mobile ≤1 MB portrait crop or poster-only. Poster: AVIF/WebP ≤100-150 kB, preloaded (`<link rel="preload" as="image" fetchpriority="high">`) since the poster can be the LCP time.
- Respect `prefers-reduced-motion` (show poster, no autoplay) and consider `navigator.connection.saveData` to skip the video on data-saver — important for Pakistani/Indian mobile visitors on metered data (inference; not sourced here).
- For portfolio-scale traffic, put the files in `/public` or Vercel Blob (CDN included) — no need for Mux/Cloudinary for a 1-2 MB loop. Use Mux (free tier) or Bunny only for the longer sound-on intro if adaptive streaming is wanted.
- If he used the "matched solid background" trick from Q2, he can skip alpha entirely and ship plain AV1 + H.264 — most robust option across Chrome Android/Safari.

## 4. Authenticity & perception: AI avatar/deepfake-style video of the candidate vs a real self-recorded intro

### Takeaway
There is no survey specifically on recruiters' reaction to AI-avatar portfolio intros, but the hiring climate in 2025-2026 is dominated by deepfake-candidate fraud fears, so an undisclosed photoreal AI "you" carries real downside; recruiters report detecting avatars through overly polished, never-faltering delivery rather than visuals. Disclosure and keeping a genuine element (his real voice or a real recorded intro) are the consistent recommendations; a stylized/obviously-designed AI character reads as a creative choice, a photoreal one reads as a possible fake.

### Cited Findings
- Checkr's 2025 survey of 3,000 US managers: 62% of hiring professionals believe job seekers are now better at faking identities with AI than HR teams are at detecting them; only 13% disagreed — [Checkr, The Hiring Hoax 2025](https://checkr.com/resources/articles/hiring-hoax-manager-survey-2025).
- A cybersecurity firm demonstrated a fake job applicant can be deepfaked into existence in ~70 minutes — [HR Dive](https://www.hrdive.com/news/fake-job-applicant-deepfake-70-minutes/745924/).
- Coverage of AI job-seeking describes recruiters encountering deepfaked/impostor candidates and AI-generated applications at scale — [The Week](https://theweek.com/tech/deepfakes-and-impostors-the-brave-new-world-of-ai-jobseeking); [NextShark](https://nextshark.com/job-recruiters-ai-resumes-deepfakes). Gartner forecast (secondary report) that up to 1 in 4 candidate profiles globally could be fake by 2028 — reported via [InteleScreen](https://intelescreen.com/deepfake-candidates-2026/) (forecast, secondary).
- A Sydney recruiter (Lana Kersanava) said candidate avatars look realistic at first but she ended interviews after ~5 minutes; the tell was answers delivered with polish that never faltered; she disqualified three candidates; the article says nothing makes an undisclosed avatar acceptable — [The Next Web](https://thenextweb.com/news/ai-avatars-job-interviews-candidates-recruiters).
- Candidates themselves dislike AI-avatar interviewers, seeing them as a sign a company cares little about recruiting/depersonalising — [TechBuzz](https://www.techbuzz.ai/articles/ai-avatars-now-screen-job-seekers-in-video-interviews); [Futurism](https://futurism.com/artificial-intelligence/footage-ai-job-interviewer-berserk).
- A recruitment-avatar vendor's own guidance: use avatars for mass outreach, switch to real video for meaningful interactions; audiences spot generic AI content; recommend hybrid (avatar overview + personal recording) — [Simli on DEV](https://dev.to/simli_ai/5-tips-for-using-digital-avatars-in-recruitment-videos-38cf).
- Video résumé surveys are old and mixed: Robert Half 2008 — only 24% of senior execs would accept video résumés, 58% would reject; CareerBuilder/Harris 2007 — 60% of 2,200 hiring managers had "some interest"; Vault 2007 — ~4 in 5 UK employers happy to watch one but only 17% had — [Plansponsor](https://www.plansponsor.com/most-hiring-managers-bar-video-resumes/); [Management-Issues](https://www.management-issues.com/news/4054/smile---youre-on-video). Employers also feared discrimination claims from viewing personal info in video — same sources.
- SynthID is embedded in all Veo outputs and is robust to cropping/compression, so an AI hero is machine-detectable as AI regardless — [AIFreeAPI SynthID guide](https://www.aifreeapi.com/en/posts/veo-3-1-watermarks-synthid).

### Inferences
- For a freelancer selling to international clients (Japan, India, Gulf, community orgs), trust is the product. A photoreal AI clone speaking with a synthetic voice risks the "is this person real?" question — exactly what remote-hiring fraud has trained clients to ask about Pakistani/offshore developers. A clearly stylised character (3D/Pixar-like or illustrated) avoids the deepfake reading and signals creativity; a photoreal clone should be disclosed ("AI-animated from my photo") and paired with proof of reality (real photo, real LinkedIn, a real recorded clip, a Calendly call).
- A real 30-60 s self-recorded intro beats AI when: the goal is hiring/high-ticket client trust, accent and personality are selling points, or the video will be watched with sound. AI wins for: a silent, decorative, looping hero motion where nobody is meant to "hear" him; a stylized brand mascot version of himself.
- Practical hybrid (recommended): AI-animated or cinemagraph silent hero loop (decorative, with a small "AI-animated portrait" note) + "Watch my 45-second intro" button that plays a REAL self-recorded video with captions. This mirrors the vendor hybrid advice and keeps authenticity where it matters.
- Uncanny-valley risk points: hands/gestures, teeth during speech, eye-line drift, lip-sync on non-English names, mismatched accent. B&W grading and shorter clips reduce visible artefacts.

## 5. Alternatives if he does NOT want AI video (photo direction, spotlight/B&W, cutout, cinemagraphs, 2.5D depth parallax)

### Takeaway
A professionally directed full-body shoot (on black or seamless paper, hard top spotlight, B&W grade) plus 2.5D depth-map parallax or a subtle cinemagraph loop can deliver the "cinematic" feel of the references with zero authenticity risk; DepthFlow (offline render to a seamless loop video) and three.js depth-map shaders (interactive) are the main techniques, with an image fallback for no-WebGL.

### Cited Findings
- DepthFlow: an image-to-parallax shader that renders up to 8K50 on an RTX 3060, supports seamless loops, and uses Depth-Anything-V2 depth models; licensed AGPL-3.0 (check implications) — [DepthFlow on PyPI](https://pypi.org/project/depthflow); [DepthFlow Hugging Face README](https://www.huggingface.co/spaces/BrokenSource/DepthFlow/blob/main/README.md).
- Browser real-time 2.5D: three.js + GLSL reading a greyscale depth map per pixel; drawbacks are per-pixel fragment cost 60x/s, need for aligned textures, and a blank screen without JS/WebGL unless a fallback image is provided — [FreeFrontend 2.5D parallax shader (May 2026)](https://freefrontend.com/code/halloween-2-5d-parallax-shader-2026-05-07/).
- Lightweight options: `3dify` npm (mouse/touch parallax from depth map, work-in-progress) — [npm 3dify](https://www.npmjs.org/package/3dify); Framer marketplace "3D image depth map" component — [Framer](https://www.framer.com/marketplace/components/3d-image-depth-map).
- Depth-map edges (hair, shoulders) are where estimates smear; inspect and hand-clean those areas — [DepthFlow HF README / search synthesis](https://www.huggingface.co/spaces/BrokenSource/DepthFlow/blob/main/README.md) (weakly sourced; general practice).
- Jake Archibald recommends building animations with web tech instead of video where possible — [Jake Archibald](https://jakearchibald.com/2024/video-with-transparency/).

### Inferences
- Photo direction brief (synthesis for a photographer in Lahore/Karachi/Islamabad):
  - Shots: full-length standing (hands relaxed / one hand in pocket / mid-gesture), three-quarter seated at desk with laptop (for the B&W reference), tight portrait; each at 45-60 MP or highest res; 3-5 s bursts for frame-picking.
  - Lighting for "stage spotlight": single hard source (bare reflector/snoot or fresnel) high and slightly front, on matte black backdrop, optional rim light to separate the navy blazer from black; meter for skin, let background fall to pure black (so it merges with a dark site — no cutout needed).
  - Cutout-friendly alternate: same poses on mid-grey or cream seamless with soft, even light so AI background removal is clean.
  - Short video takes: 10-20 s of locked-off 4K/60 video in each pose (blink, breathe, subtle smile, small hand gesture) — raw material for a real cinemagraph or a subtle real "living photo" loop, and for a real self-recorded intro.
- Cinemagraph: freeze everything except breathing/blinking/hair or a laptop screen glow; mask in After Effects/DaVinci Resolve (free) and loop 4-6 s; encode as muted AV1/H.264 (<1 MB).
- 2.5D: render a 6-8 s DepthFlow seamless loop offline (avoids AGPL code shipping in the site and GPU cost on visitors) or build a small mouse-reactive three.js/OGL depth shader with `prefers-reduced-motion` and image fallback.
- His existing headshot (dark grey backdrop, navy blazer) already suits a dark theme and depth-parallax treatment; B&W grading would unify it with reference (b).

## 6. Project media: showcasing live client sites (scroll recordings, mockups, full-page captures, codecs, tools, anonymizing client financial data)

### Takeaway
Use short (6-12 s) muted scroll/interaction loops recorded at 2x DPI and encoded as AV1/H.264 MP4 (+ WebM), with poster stills and lazy loading below the fold; on Windows, Cap (free/open-source, $58 commercial licence) or FocuSee replace Mac-only Screen Studio; full-page stills via Chrome DevTools "Capture full size screenshot". The inventory dashboard must not show real client financials — rebuild it with seeded demo data (preferred) or blur, and check NDAs/permission for every client.

### Cited Findings
- Screen Studio is Mac-only, subscription ~$29/mo or ~$9/mo billed yearly — [ScreenSnap: Screen Studio for Windows](https://www.screensnap.pro/blog/screen-studio-for-windows); [Hinto AI alternatives](https://hintoai.com/blog/alternatives/screen-studio-alternatives) (vendor-adjacent roundups).
- Windows alternatives with auto-zoom: Cap — runs on Windows/macOS, free for personal use, no time limit on local recordings, click-generated zoom segments, MIT-licensed source; one source says a $58 one-time Desktop License for commercial use — [Hinto AI](https://hintoai.com/blog/alternatives/screen-studio-alternatives); [Matte](https://matte.app/blog/best-screen-studio-alternatives-2026). FocuSee — Windows & Mac, up to 4K/60 export; pricing conflicting ($49.99 first-year promo vs $19.99/mo, $99.99/yr, $199.99 lifetime v2.x) — [FocuSee comparison](https://focusee.imobie.com/compare/screen-studio-alternative.htm); [GuideClarity](https://guideclarity.com/alternatives/screen-studio). OBS Studio is free and cross-platform but has no automatic zoom — [ScreenSnap](https://www.screensnap.pro/blog/screen-studio-for-windows).
- Chrome DevTools full-page capture: F12 -> Ctrl+Shift+P -> "Capture full size screenshot" saves a PNG of the whole page; also "Capture node screenshot" and "Capture area screenshot" — [Umaar dev tips](https://umaar.com/dev-tips/151-screenshot-capture/); [freeCodeCamp](https://www.freecodecamp.org/news/how-to-take-full-page-screenshots-in-chrome-without-extensions/). Limits: fixed/sticky headers get baked in or repeated, lazy-loaded content may be blank unless you scroll first, very tall pages may truncate; CDP `Page.captureScreenshot` with `captureBeyondViewport` for scripted captures — [Fullpage-screenshot article (extension vendor)](https://fullpage-screenshot.ai.studio/articles/devtools-full-page-screenshot-limits).
- Encoding: serve at displayed size; strip audio from decorative loops — [ImageKit](https://imagekit.io/blog/nextjs-video-optimization/). MP4 for compatibility, WebM for web optimisation; use FFmpeg; lower resolution/bitrate for mobile; use a CDN — [Next.js Videos guide](https://nextjs.org/docs/app/guides/videos). AV1 gives the smallest files in Archibald's tests (stacked AV1 460 kB vs HEVC 1.14 MB for the same clip) — [Jake Archibald](https://jakearchibald.com/2024/video-with-transparency/).
- NDA/confidential data: read what the NDA defines as confidential (financial info, customer data, etc.) and any publicity clauses — a portfolio is public; redact by blurring logos, replacing client names with placeholders, sanitising data; some practitioners password-protect detailed case studies; lead with impact and process; track NDA expiry — [Fueler NDA case study guide](https://www.fueler.io/blog/how-to-write-case-study-client-work-under-nda); [Blind discussion](https://www.teamblind.com/post/how-do-you-include-projects-in-your-portfolio-while-avoiding-to-put-in-confidential-information-ujkyyyh1); [UX Planet on GDPR/NDA in portfolios](https://uxplanet.org/your-work-their-data-navigating-gdpr-and-nda-in-design-portfolios-40a21ea0b64d).

### Inferences
- Recording spec (synthesis): record each live site in a clean Chrome profile (no extensions, no bookmarks bar) at a 1440x900 or 1920x1080 window with Windows display scaling 200% (or DevTools device emulation at DPR 2) for crisp text; 60 fps capture, export 30 fps; 6-12 s per loop: hero -> smooth scroll -> one key interaction (search/filter on the machinery marketplace, booking widget on the resort, prayer-times/donations on the mosque SaaS).
- Encode each loop: AV1 MP4 (primary, ~0.5-1.5 MB) + H.264 MP4 fallback (`-movflags +faststart`, no audio) + optional VP9 WebM; poster = first frame as AVIF/WebP. Below-the-fold project videos: `preload="none"` + IntersectionObserver to set `src`/play when visible, pause when off-screen.
- Mockups: browser-chrome frames or device frames can be done in CSS/Figma rather than Mac-only Rotato (Rotato appears to be a macOS app — verify); a laptop/phone composite for each project plus one full-page "long scroll" image inside a fixed-height frame that scrolls on hover is a common premium pattern.
- His current 1366x640 screenshots are too small for a 2026 retina hero/case-study (they'll look soft at 2x); recapture at DPR 2 (≥2732px wide).
- Inventory/distribution dashboard: do NOT publish real financial figures. Best: run the desktop app against a seeded demo database (realistic but fake company names, SKUs, PKR amounts, dates), label it "demo data". Alternative: Chrome DevTools/element edits or a post-production blur/mosaic on every numeric cell — blur is visibly "censored" and less premium than seeded data. Get written client permission to show any client UI at all (including the Japanese and Indian sites' branding).
- Accessibility/perf: each project loop `muted playsinline loop`, `aria-hidden` if decorative with an adjacent text description; honour `prefers-reduced-motion` by showing posters.
